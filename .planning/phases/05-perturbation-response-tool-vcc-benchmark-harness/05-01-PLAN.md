<interfaces>
From annotation/summary.py (Phase 4, already exists) -- the established dataclass-per-result-type convention this plan's perturbation/summary.py mirrors:

```python
@dataclass
class AnnotationCall:
    cluster: str
    label: str
    confidence: float
    reference_dataset: str
    ontology_term_id: str | None

@dataclass
class AnnotationSummary:
    dataset_id: str | None
    fm_calls: list[AnnotationCall]
    baseline_calls: list[AnnotationCall]
    fm_model: str
    baseline_method: str
```

This plan's own perturbation/summary.py contract (fixed here, verbatim, for Plans 02/03/04/05 to implement against). Unlike AnnotationSummary (many clusters per call), PerturbationSummary predicts ONE target gene per call -- PERT-01's own wording is "control profiles and a target gene" (singular) -- so there is exactly one model_call and one baseline_call per predict() invocation, not a list:

```python
@dataclass
class PerturbationCall:
    method: str
    target_gene: str
    predicted_expression: list[float]

@dataclass
class PerturbationSummary:
    dataset_id: str | None
    target_gene: str
    gene_names: list[str]
    model_call: PerturbationCall
    baseline_call: PerturbationCall
```

`method` is `"linear_additive"` for the learned model or `"naive_baseline"` for the baseline. `predicted_expression` length equals `len(gene_names)`. `gene_names` gives the shared gene order both calls' `predicted_expression` vectors are aligned to.
</interfaces>
