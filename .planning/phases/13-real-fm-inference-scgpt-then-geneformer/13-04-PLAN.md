<objective>
Wire Geneformer into the agent's tool-calling surface end to end: a pipeline composition function that resolves the target gene's Ensembl ID internally and validates it before inference, a new agent tool mirroring `predict_perturbation_tool`'s exact schema shape, and a real, human-verified smoke test against the isolated `geneformer_worker/` environment.

Purpose: This is the final integration plan for FM-02 -- Plans 13-02/13-03 built the dataclasses, validator, worker script, and subprocess client in isolation; this plan is where they become something the agent can actually call. Per Pitfall 3, the four-step pipeline can run for hours, so `predict_geneformer()` dispatches the blocking subprocess call via `asyncio.to_thread()`, mirroring `ingest/census.py`'s existing precedent for blocking I/O rather than letting a multi-hour call block the agent session. Per the roadmap's explicit "validated... before inference runs" wording, `validate_ensembl_ids()` runs unconditionally before any h5ad is written for the worker, and a target gene's Ensembl ID is resolved server-side (not exposed as an LLM-facing parameter the agent could get wrong).
Output: `predict_perturbation_geneformer_tool` callable from the agent loop, plus a `checkpoint:human-verify`-gated real end-to-end run against the isolated Geneformer environment.
</objective>
