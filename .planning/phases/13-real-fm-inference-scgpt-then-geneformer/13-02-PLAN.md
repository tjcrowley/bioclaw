<objective>
Lay the foundation for Geneformer (FM-02): define the new output-shape dataclasses that later plans implement against, build the Ensembl-ID presence validator that must run before any Geneformer inference call, register the `geneformer_smoke` pytest marker, and attempt to stand up the isolated `geneformer_worker/` Python 3.10 environment (package clone + smallest checkpoint pull).

Purpose: Per 13-RESEARCH.md, Geneformer's output ("ranked gene list by cosine shift") is structurally incompatible with `PerturbationCall.predicted_expression: list[float]` -- Pitfall 4 explicitly warns against shoehorning it in. Defining the new dataclasses now (interface-first) means Plans 13-03/13-04 implement against a fixed contract instead of improvising one mid-pipeline. Per Pitfall 2, Geneformer's tokenizer fails silently (not loudly) on missing/mismatched Ensembl IDs, producing degenerate-but-exception-free results -- `validate_ensembl_ids()` is the guard the roadmap's "validated... before inference runs" wording requires, built now so Plan 13-04's pipeline composition can call it unconditionally. This plan also does the one-time, potentially slow/network-flaky environment setup (git clone + LFS pull) up front, isolated from the code-writing plans that depend on it.
Output: New dataclasses in `perturbation/summary.py`, `perturbation/ensembl.py` with a tested validator, `geneformer_smoke` marker registered, and a `geneformer_worker/` environment with its setup outcome documented.
</objective>

  <behavior>
    - `perturbation/summary.py` gains three new dataclasses (additive only, existing
      `PerturbationCall`/`PerturbationSummary` untouched):
      ```python
      @dataclass
      class GeneShift:
          gene: str
          ensembl_id: str
          cosine_shift: float

      @dataclass
      class GeneformerPerturbationCall:
          method: str  # always "geneformer"
          target_gene: str
          target_ensembl_id: str
          match_rate: float  # fraction of adata.var Ensembl IDs found in Geneformer's vocab
          ranked_genes: list[GeneShift]  # sorted by |cosine_shift| descending

      @dataclass
      class GeneformerPerturbationSummary:
          dataset_id: str | None
          target_gene: str
          call: GeneformerPerturbationCall
      ```
    - `perturbation/ensembl.py::validate_ensembl_ids(adata) -> None`: mutates `adata.var` in
      place, adding an `"ensembl_id"` column, and raises `ValueError` (message must mention
      "Ensembl") if no usable source column/index is found. Resolution order:
      1. If `"gene_ids"` is in `adata.var.columns` (the 10x MTX/.h5 ingest path -- see Don't
         Hand-Roll above): alias `adata.var["ensembl_id"] = adata.var["gene_ids"]`.
      2. Else if `"feature_id"` is in `adata.var.columns` (a plausible census/.h5ad-upload
         column name): alias from that.
      3. Else if `adata.var_names` themselves match the Ensembl ID shape (regex
         `^ENS[A-Z]*G\d+` on a majority of entries): alias `adata.var["ensembl_id"] =
         adata.var_names`.
      4. Else: raise `ValueError` explaining that no Ensembl-ID-shaped column was found and
         that Geneformer requires one (gene symbols alone are insufficient -- 13-RESEARCH.md
         Pitfall 2).
      In all three success paths, additionally strip any `.N` version suffix (e.g.
      `"ENSG00000141510.21"` -> `"ENSG00000141510"`) from every value in the new
      `"ensembl_id"` column, per Pitfall 2's version-suffix mismatch warning.
    - Tests in `tests/test_perturbation_ensembl.py` (build tiny `AnnData` objects directly,
      no ingest pipeline needed):
      1. `adata.var["gene_ids"]` present with plain IDs -> `ensembl_id` column created,
         equal to `gene_ids`.
      2. `adata.var["gene_ids"]` present with `.N` version suffixes -> suffixes stripped.
      3. No `gene_ids`, but `adata.var["feature_id"]` present -> aliased from `feature_id`.
      4. No `gene_ids`/`feature_id`, but `adata.var_names` look like Ensembl IDs (e.g.
         `"ENSG00000141510"`) -> aliased from `var_names`.
      5. None of the above (plain gene-symbol `var_names` like `"CD3D"`, no `gene_ids`/
         `feature_id` columns) -> raises `ValueError` whose message contains "Ensembl".
  </behavior>
