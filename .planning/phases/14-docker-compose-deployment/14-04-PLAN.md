ENV baked into the runtime image (Plan 14-02):
```
BIOCLAW_STORE_ROOT=/app/state/data

```
ENTRYPOINT (fixed, not a `command:`, deliberately not overridable by Compose):
```
ENTRYPOINT ["/app/docker/entrypoint.sh"]
```
`docker/entrypoint.sh` (Plan 14-02) always runs `uvicorn webapp.backend.main:app --host 0.0.0.0 --port 8000 --workers 1`, ignoring any args passed to it.

Health endpoint (Plan 14-01): `GET /api/health` -> `{"status": "ok"}`, unauthenticated.

`.env.example` (Plan 14-02) declares exactly two vars: `ANTHROPIC_API_KEY`, `BIOCLAW_WEB_PASSWORD`.

**Design decision (deliberate deviation from 14-RESEARCH.md's illustrated pattern):** The research document's "Recommended Project Structure" section illustrates GPU support via either (a) a `profiles: ["gpu"]` second service using `extends:`, or (b) a `docker-compose.gpu.yml` override file. Option (a) has a real bug: running `docker compose --profile gpu up` starts BOTH the profile-less base service and the profile-gated GPU service simultaneously if they both bind port 8000, causing a port conflict. This plan uses option (b) exclusively — one `backend` service, no `profiles:` key at all, GPU passthrough merged in via `-f` override file composition.
</interfaces>

  <name>Task 1: docker-compose.yml + docker-compose.gpu.yml</name>
  <files>docker-compose.yml, docker-compose.gpu.yml</files>
  <action>
    Create `docker-compose.yml` at the repo root (Compose Specification — no
    top-level `version:` key needed, matches current `docker compose` v2
    conventions):
    ```yaml
    services:
      backend:
        build: .
        image: bioclaw:latest
        ports:
          - "8000:8000"
        env_file:
          - .env
        environment:
          ANTHROPIC_API_KEY: ${ANTHROPIC_API_KEY}
          BIOCLAW_WEB_PASSWORD: ${BIOCLAW_WEB_PASSWORD}
        volumes:
          - bioclaw-state:/app/state
        healthcheck:
          test: ["CMD", "python3", "-c", "import urllib.request; urllib.request.urlopen('http://localhost:8000/api/health')"]
          interval: 10s
          timeout: 5s
          retries: 5
          start_period: 20s
        restart: unless-stopped

    volumes:
      bioclaw-state:
    ```
    No `command:` or `entrypoint:` key anywhere in this file — the
    single-worker constraint (DOCK-01 criterion 2) must come exclusively
    from the image's baked-in `ENTRYPOINT` (Plan 14-02), not from Compose.
    This is deliberate and verified in Task 2.

    Create `docker-compose.gpu.yml` as a pure override — same service name
    (`backend`), only the GPU-relevant keys, no rebuild of `build:`/`ports:`/etc:
    ```yaml
    services:
      backend:
        deploy:
          resources:
            reservations:
              devices:
                - driver: nvidia
                  count: 1
                  capabilities: ["gpu"]
    ```
    Usage documented in this plan's `<done>` and later surfaced in Plan
    14-05's README: `docker compose up` alone is CPU-only (always works,
    satisfies DOCK-01 criterion 1 unconditionally); `docker compose -f
    docker-compose.yml -f docker-compose.gpu.yml up` merges GPU passthrough
    onto the same single `backend` service (satisfies the "optional GPU
    worker" framing in the phase goal without a second service or a
    `profiles:` key).

<task type="auto">
  <name>Task 2: Smoke test script</name>
  <files>scripts/docker_compose_smoke_test.sh</files>
  <action>
    Create `scripts/docker_compose_smoke_test.sh` (executable, `chmod +x`):
    ```bash
    #!/bin/sh
    # Builds and starts the Compose stack, polls the health endpoint, and
    # tears down. Asserts the --workers 1 constraint is structural (no
    # command:/entrypoint: override present in the resolved config) --
    # DOCK-01 criteria 1 and 2.
    set -e

    echo "==> Validating compose config has no command:/entrypoint: override (DOCK-01 criterion 2)"
    if docker compose config | grep -qE "^\s*(command|entrypoint):"; then
      echo "FAIL: docker-compose.yml declares command:/entrypoint: -- the single-worker constraint must come only from the image's ENTRYPOINT" >&2
      exit 1
    fi

    echo "==> Building"
    docker compose build

    echo "==> Starting"
    docker compose up -d

    cleanup() {
      docker compose logs backend || true
      docker compose down
    }

    echo "==> Polling /api/health"
    ok=0
    for i in $(seq 1 30); do
      if curl -sf http://localhost:8000/api/health >/dev/null 2>&1; then
        ok=1
        break
      fi
      sleep 2
    done

    if [ "$ok" -ne 1 ]; then
      echo "FAIL: /api/health did not become healthy in time" >&2
      cleanup
      exit 1
    fi

    echo "==> Healthy. Tearing down."
    docker compose down
    echo "==> Smoke test passed."
    ```
  </action>
